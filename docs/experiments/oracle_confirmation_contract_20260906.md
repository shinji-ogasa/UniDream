# 固定候補を追加期間で確認するための実装

前回の先物50%縮小候補は維持した。今回、新しい予測や売買成績は計算せず、追加期間へ適用するためのカレンダー、受信時刻、固定候補全体の集計を実装した。これは確認手順の一部で、独立確認の完了、将来監視の開始、実運用の許可を表さない。

## 実装した範囲

[設定](../../configs/oracle_confirmation_contract_20260906.yaml)と[契約コード](../../unidream/experiments/oracle_confirmation_contract.py)は、既に固定した4候補・8対照を維持する。重み、期間数、指標、費用、特徴量の支持集合を変更して通過させる設定は受け付けない。21件の必須ソース／メタデータをSHA-256で照合し、候補ファイルは独立して照合する。重複・別名パスによるハッシュの上書きも拒否する。これはファイル内容の整合性であり、データ受信証拠の真正性を保証するものではない。

新しい評価開始Sをtest開始へ合わせ、fit [S−24か月,S−6か月)、scale [S−6か月,S−3か月)、interval [S−3か月,S)、evaluation [S,S+3か月)とした。古いfoldのval_startへ合わせてしまうと1四半期ずれるため、別関数で定義した。評価開始を同じにした合成カレンダーでは、既存delay実装の各マスクと一致する。

|---|---|
| 四半期 | test26–37、12期間 |
| 評価区間 | [2026-10-16 13:45 UTC, 2029-10-16 13:45 UTC) |
| 最初の予定決定 | 2026-10-16 18:00 UTC |
| 最初のfit区間 | [2024-10-16 13:45 UTC, 2026-04-16 13:45 UTC) |

## 受信時刻と実行時刻

[受信メタデータの検証](../../unidream/experiments/oracle_receipt_support.py)は、特徴量の起点tと判断期限を分ける。新しい設計では期限をt+60秒に固定し、次の15分足始値より前とする。これはアーカイブで使った名目的なt時点の情報集合に受信制約を加える別の運用条件であり、当時の遅延が60秒以内だったと推定したものではない。

- 特徴量に使えるのは、tの直前までの確定足。期限を遅らせてもtの未確定足を追加しない。
- Binance形式のclose時刻はopen+15分−1ms。確定足の受信はopen+15分以降でなければ不整合として拒否する。
- 期限と同時の受信は許可し、1nsでも遅ければ不使用。受信時刻が不明な行を、隣の行や後日のアーカイブから補完しない。
- 現在始値open[t]の取得、実際の注文提出、入力値の正しさ、受信証拠の真正性、全ローリング窓の網羅性は、この関数だけでは証明しない。

既存delay共通マスクは、technical/perp0/1/4だけでなく、旧flow全列・derivative全8追加特徴・trailing variance24/96/672/2880の可用性も含む。その依存集合を維持し、将来の受信期限時点で再構成する必要がある。直接使用する特徴だけへ削ると別の支持集合になる。今回の行単位メタデータ関数を、90日などの必要履歴全体が完全だったという証拠に使わない。

相場分類も元コードどおり、各四半期の最初の6時間予定決定における過去90日モメンタムと7日ボラティリティを使う。13:45の四半期境界そのものの分類や、その後の実現四半期リターンへ置き換えない。

## 何を「条件達成」と数えるか

[候補全体の集計関数](../../unidream/experiments/oracle_confirmation_contract.py)は、12期間すべての4候補・8対照、および5つの予測系列を要求する。欠けた四半期を平均から落として成功にすることを拒否する。経済・予測間の分類、予測間の採点行数も照合する。全15分足の完全性やモデル出所は別のアダプターで検証する必要があり、集計結果だけから認証済みとは扱わない。

| 主な確認成分 | 個数 |
|---|---:|
| 4候補 ×（全体＋3分類）× 2費用 × AlphaEx／DD改善 | 64 |
| 2予測 ×（過去平均／自身の元予測）×（全体＋3分類）のMSE改善 | 16 |
| 重複しない主成分 | 80 |

同じ予測を保有継続とfallbackが共有するため、候補ごとの参照は24条件、合計96参照となる。80や96は独立な試行数でも標本数でもない。経済指標は四半期平均AlphaExと−MaxDDDelta、予測指標は比較相手のMSE−候補MSEで、すべて正が好ましい。四半期を等重みで集計し、負の成分や分類の不足をほかのよい成分で相殺しない。MAE、IC、ゼロ／fit_mean比較などは事前に定める記述的な副指標で、主条件の失敗を救済しない。

集計の「観測指標と期間数の条件」は、未検証のデータ出所や将来保証の判定と分けた。全合成値をよくしても、p値・調整p値・同時信頼水準はnullで、高確率汎化はfalseのままである。無限大、NaN、複素数、真偽値、配列などを経済・予測スカラーとして受け付けず、有限な大きな値の平均計算でもオーバーフローを防ぐ。

## 一次資料から分かった統計上の境界

候補1つの全条件を同時に満たす主張はintersection-union testとして整理できる。有効な片側p値が各条件にあれば、その最大値を候補のp値とできる。この論理は各条件のp値が有効であることを前提とする。[Berger–Hsu (1996)](https://doi.org/10.1214/ss/1032280304)

4候補のどれかを成功と宣言する部分には、例えばHolmの4候補補正を使う。最初の閾値は0.05/4=0.0125で、相関があることだけを理由に4候補を1候補へ減らさない。これは妥当な個別p値を前提とし、「95%の確率で将来勝つ」という意味ではない。[Holm (1979)](https://www.jstor.org/stable/4615733)

系列依存を扱うbootstrapの正当化には極限分布とその推定の整合性などが必要で、12四半期・分類ごと3期間があるだけでは満たしたといえない。[Romano–Wolf (2005)](https://doi.org/10.1198/016214504000000539) 少数グループでの推論にも、各推定量の独立性、偏り、分布に条件がある。四半期内に15分足が多数あることは、それらの条件を自動的に証明しない。[Ibragimov–Mueller (2010)](https://doi.org/10.1198/jbes.2009.08046)

したがって今回の実装は記述的集計に限定し、統計的有意性を計算するエンジンを未設定にした。12期間で3分類それぞれ最低3期間になる保証もなく、欠けた分類を既に利用した過去期間で埋めたり、成績がよくなるまで期間を延ばしたりしない。将来確認は、全候補・全経路を保持した別の実行仕様と、事前に正当化した推論方法が必要である。

## 検証と残る作業

27件の新規合成テストで、既存マスクとの一致、成熟境界の厳密な不等号、ラベルと推論の分離、受信期限、後日補完の禁止、完全な候補・期間集合、不正な数値、ソース結合の上書き拒否を確認した。独立レビューの指摘を修正してから全テストを再実行した。全テストは **564 tests OK (56.618s)**。[検証記録](oracle_confirmation_contract_evidence_20260906/verification.json)と[独立レビュー](oracle_confirmation_contract_evidence_20260906/independent_review.md)、[証拠manifest](oracle_confirmation_contract_evidence_20260906/manifest.json)を保存した。

[preflight](oracle_confirmation_contract_evidence_20260906/preflight.json)はカレンダーとソースのみを検証し、`ready_for_outcome_scoring=false`を返す。最初の実装途中のpreflightは未登録の草案としてローカルに残し、レビュー修正後のv2を今回の証拠として保存した。どちらも市場成績を含まない。

次は、固定した学習・校正・予測・自分自身の保有状態に基づく注文経路を、新しい評価開始へ適用するアダプターを作る。まず既存開発8期間で元成果物との一致を確認し、受信時刻のある入力では合成遅延も検証する。追加のtest/outerは別の固定登録に基づくreport-onlyとし、その結果から候補や欠損ルールを選び直さない。過去期間の利用履歴監査、旧選択ロック、P1の範囲は維持する。

学習・校正用の過去アーカイブを学習実行時点のスナップショットへ固定する条件と、新しい評価予測を実際の受信期限に間に合わせる条件は分けて実装する。当時の受信時刻がない過去アーカイブを、受信履歴まで復元したデータとは扱わない。
