# 学習から売買までの固定手順を再現

新しい学習・校正処理でモデルを再学習し、既存8四半期の予測・注文・損益を再現できた。**40予測、96注文系列、80判断トレース、通常／費用2倍の192会計結果は、保存済み結果との差がすべて0**だった。校正配列と係数も一致した。

これは改善候補の再現性の確認であり、新しい精度改善や独立した期間での成功ではない。先物50%・保有継続候補の既存成績（四半期平均AlphaEx +3.613pt／MaxDDDelta −5.388pt、費用2倍 +3.349pt／−5.305pt）はそのままである。過去平均やゼロ予測に対するMSEの未達、分類別2/4/2期間の不足も変わらない。

## 固定してから実行した内容

[登録文書](oracle_frozen_procedure_parity_registration_20260906.md)、[設定](../../configs/oracle_frozen_procedure_parity_20260906.yaml)、実装・テスト・preflightをコミット **f284124** で固定してから実データを使う再学習を実行した。

旧validation fold5–12は、新しいカレンダー関数のtest fold4–11と同じ日付である。今回使ったのは[2021-04-16 13:45 UTC,2023-04-16 13:45 UTC)だけで、後続のtest/outerを新しく採点していない。

[学習ヘルパー](../../unidream/experiments/oracle_frozen_forecasts.py)は、technicalとperp_delay0のRidge平均予測を2つ、全候補で共有するtechnical HGB分散予測を1つ、各四半期で学習する。モデル構造、入力、重み、seed、18/3/3か月の学習・校正手順は維持した。先物の分散予測は各候補の意思決定に使っていないため、この処理では学習しない。

[実行・一致確認コード](../../unidream/experiments/oracle_frozen_procedure_parity.py)は、モデル学習から校正、5つの平均予測、各候補自身の保有量に基づく注文、両コストでの会計までつなぐ。校正期間の平均には既存のmath.fsum、平均予測の補正には既存のnp.mean、50%混合には既存の凸結合を使い、演算順も合わせた。

## 独立した比較と実装テスト

[独立監査](oracle_frozen_procedure_parity_evidence_20260906/independent_parity_audit.json)でも全対象が一致した。543件のファイル結合を照合し、48件の古い学習・推論・採点マスクのハッシュ、40予測、96注文、192会計結果、80トレース、16校正配列、8校正記録を確認した。元の239件の固定参照ハッシュは変えていない。

監査側で保存予測からMSE、MAE、符号精度、ゼロ／学習平均比較、rank ICを再計算した最大差は **1.73e−18**。これは数値計算の一致確認であり、別の学習アルゴリズムや独立した会計シミュレーターで再度学習・運用した結果ではない。

新規17テストと全 **581 tests OK (56.488s)** を実行前に通過した。合成テストには、評価ラベルを文字列へ変えても予測が変わらないこと、intervalだけを変えるとquantileだけが変わること、504件のRidge予測のスカラー計算による照合、未来ラベルから注文を分離する条件、NaN・時刻・注文の完全一致、空の再開manifestの拒否を含む。

再開時には全33成果物、12方策・5予測、各ハッシュと参照値を再照合する。再開時の最大差欄は初回に保存した値であり、再比較の最大差を再集計した値ではない。この限定は登録時に明記しており、今回の実行は全8期間を新たに計算して完了した。別の独立監査では最大差も再計算している。

## 実行環境と残る境界

実行ログにはscikit-learnの行列積から96件のRuntimeWarningが出た。最終予測はすべて有限で、保存結果との完全一致も通った。[スカラー監査](oracle_frozen_procedure_parity_evidence_20260906/scalar_ridge_audit.json)では、16個のRidgeモデルについて9,884件の校正予測と5,172件の推論予測、合計15,056件をPythonの減算・除算・math.fsumで再計算した。最大差は校正5.20e−18、推論3.47e−18で、固定許容誤差内だった。scaler・係数・切片はすべて有限で、スケールは正だった。この監査は警告の原因や学習・HGB計算全体の正しさを特定したものではない。

[preflight](oracle_frozen_procedure_parity_evidence_20260906/preflight.json)のSHAは `4dcf2dacf2ca6a43d23d90ffc0c8cd4d8bdfd3be6015978e3a98baae221a86ae`、[実行時登録](oracle_frozen_procedure_parity_evidence_20260906/registration.json)は `886f7a1a4fe494f7c5131ba6eae6384cd9d1ae64d048fecbabd87247c3d667f5`、[結果](oracle_frozen_procedure_parity_evidence_20260906/results.json)は `c19b772e4f53b5a749839553b82c439ef4684a2ec9efe523464c533e8beed366`。

今回の実行器は同じ8期間の再現だけを許可する。新しい学習ヘルパーは他の期間へ適用できる部品になったが、追加期間のデータ取得・品質確認・実行登録は別に必要である。真に将来の予測を記録するには、実際の受信時刻・現在始値・注文提出・約定時刻の証拠も必要となる。

次は固定した4候補と8対照について、追加の再利用期間を扱うデータだけの事前確認と、report-only評価の登録を進める。後続のtest/outerで候補や重み、欠損ルールを選び直さず、過去データの再生を独立した将来確認と呼ばない。以前の選択ロックやP1の範囲は維持する。
