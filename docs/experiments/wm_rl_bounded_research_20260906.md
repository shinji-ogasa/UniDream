# UniDream WM → BC → imagination actor-critic: bounded research proposal

2026-09-06. Read-only source and primary-literature review; no real fits, forecasts, labels, economic calculations, or deployment. Requested source: `configs/plan011_overlay_actor_v31_relative_constraint_ac.yaml` and `unidream/actor_critic/imagination_ac.py` in the oracle-feature-frontier worktree. Source bindings are in the adjacent `.sources.json` file.

## Prerequisite before spending training budget

The exact requested configuration has an action/reward-support problem which coefficient tuning cannot establish away. `world_model.action_context: actionless` makes `train_wm.py:1238–1265` ignore dataset actions and use a constant benchmark action when `reward_mode=excess_bh`. `_compute_net_returns` at lines 885–906 computes `p*r − cost*abs(delta_p) − benchmark*r`. With p=benchmark=1, these training rewards are zero after the first sequence entry; the first entry contains the synthetic flat-to-benchmark cost. Conversely, `imagination_ac.py:492–502` supplies variable actor positions to `TransformerWorldModel.imagine_step`, whose forward pass consumes those positions. Auxiliary return/risk heads can still learn market information, but this does not identify the reward head's response to untrained action variation. This is an algebraic source finding, not a numerical performance diagnosis. Check whether the actual chosen runner already supplies a different, verified reward path. Do not merely switch to `world_model.reward_mode: absolute`: under this actionless branch the default action becomes zero, so its reward targets are also zero.

Two further implementation limits:

* `world_model.n_ensemble: 1` plus `var(unbiased=False)` in `ensemble.py:150–163` makes disagreement exactly zero for finite priors. Raising `world_model.disagree_scale` alone does nothing. Independent latent categorical models also need a common interpretation before category-wise disagreement can be treated as calibrated model error; the present statistic is not an error bound.
* `world_model.done_scale: 0.0` disables done-loss learning, while imagination still uses sigmoid done probabilities in continuation. Check this fixed behavior in the runtime contract before interpreting a nominal horizon as effective duration. Do not covertly change it only for a promising arm.

If the reward prerequisite is unresolved, the most useful finite experiment is its registered implementation/semantic correction and a paired BC-versus-AC comparison. It is not scientifically useful to claim a strongest RL result after a grid over an unidentifiable reward head. No architecture redesign is required in principle: a market WM can remain actionless and predicted market returns can be converted to position/cost rewards by explicit accounting, but that conversion is a new, separately verified reward contract, not an existing YAML-only toggle.

## Four modest comparisons, after the reward contract is fixed and frozen

All numeric alternatives below are deliberately simple fixed probes, not values implied optimal by the papers. Keep Transformer dimensions, feature order, WM/BC checkpoint bytes, train chronology, seeds, batch sizes, real-price execution, costs, selection scope, and inference thresholds identical within each comparison. `online_wm_interval: 0` stays zero. Each arm starts from the same BC actor and a fresh identically seeded critic; do not continue one arm into another.

| ID | Exact existing configuration change | Falsifiable question and failure mode |
| --- | --- | --- |
| A: short imagination | `ac.horizon: 8 → 4`; all other settings unchanged | Does reducing recursive model use improve realized validation AlphaEx/MaxDD against the same BC and 8-step AC? MBPO motivates short rollouts branched from real states, not a guarantee that 4 is optimal. Four 15m model steps are a nominal one-hour imagination horizon, not a four-step change to the 6h deployment decision clock. Failure: shorter returns depend more on a weak bootstrap critic and miss drawdown/recovery dynamics. |
| B: retain BC weight | `ac.alpha_final: 0.05 → 0.35`, retaining `alpha_init: 0.35` | With both endpoints .35, the BC mixture is constant even if the existing adaptive decay speed changes. Does AC retain useful learned BC behavior without exploiting model error? Keep `td3bc_alpha: 0.35` and prior coefficients unchanged. Failure: a weak/hindsight-derived BC teacher caps improvement; matching BC is not incremental RL value. |
| C: stronger drawdown surrogate | `ac.relative_dd_coef: 2.5 → 5.0`; leave `relative_terminal_dd_coef: .35`, `alpha_floor_coef: 2.0`, and `relative_cvar_coef: .20` unchanged | Does one fixed increase in the existing risk penalty improve actual MaxDDDelta without losing AlphaEx? This remains a soft penalty on the registered reward path, not a constraint guarantee. Failure: collapse toward B&H or excessive underweight; lower relative-path DD may coexist with worse strategy-vs-B&H MaxDD. |
| D: stronger execution anchoring, optional | `ac.prior_flow_coef: .004 → .020`; keep other prior and BC terms unchanged | Does explicitly retaining the BC controller's softly executed inventory change improve realized cost/turnover and prevent actor drift? The existing `_prior_anchor_loss` computes a smooth-L1 loss between current and frozen-BC soft execution flows. Failure: soft-controller parity may not preserve discrete thresholded orders, or retain bad BC behavior. |

For a quick finite matrix use unchanged AC + A + B + C, plus the frozen BC endpoint and B&H. D is an alternative to C if execution drift is the predeclared question, not a late fifth trial. Do not form A×B×C×D combinations. If only one extra AC run is affordable, choose A before observing new outcomes and retain the unchanged AC/BC/B&H controls; alternatively register A+B as one combined candidate and explicitly forgo component attribution. Reuse one identical WM/BC fit per fold across AC arms; this saves WM retraining. Freeze `ac.max_steps: 300`, checkpoint selection rules, and all adjustment-rate choices before observing results. Existing `val_adjust_rate_scale_grid: [.7,1,1.3]`, `restore_best_val_checkpoint: true`, and adaptive validation use already enlarge the selection procedure: either keep them identically registered and counted, or prospectively fix scale=1 and endpoint selection in every arm, including a fresh control. Never silently freeze them only for alternatives.

No reliable wall-clock or weekly-token estimate can be inferred from these settings alone. The bound is a number of fixed arms, maximum training steps, and a single pass through the chosen identical development folds. Stop after that family, retain failures, and use subsequent periods only for the previously frozen report/confirmation role.

## Why not an uncertainty or feature grid now

MOPO's theoretical lower bound assumes an admissible error bound on relevant model transitions/rewards; the paper explicitly says its practical uncertainty proxy lacks that guarantee. UniDream's latent-prior disagreement is a different proxy. A meaningful uncertainty comparison would require `world_model.n_ensemble: 3` and paired AC `world_model.disagree_scale: 0` versus `.1` on those same three frozen models, plus verification that latent disagreement measures meaningful prediction error. That adds WM training and ensemble-parity work, so it is deferred from the quick matrix rather than labelled an existing n=1 regularizer.

The current feature contract already includes funding/basis (data knobs `include_funding: true`, `include_mark: true`, `include_oi: false`) and causal technical/RV features. Preserve these now. `augment_with_context_features` and `augment_with_funding_context_features` exist, but source search did not find a wired Plan011 configuration call path; do not invent a toggle. A later single signed-flow block could use only completed bar quote volume Q and taker-buy quote B: `I_m(t,24)=sum_{j=t−24}^{t−1}(2B_m(j)−Q_m(j))/sum Q_m(j)` for Spot and UM, with their difference as the third column. Reject missing/zero-denominator support, preserve the scheduled grid, register common eligibility, and bind receipt/close availability; do not impute missing flow as neutral. This changes the feature/input contract and requires a new WM/BC fit. Cont et al. establish short-interval contemporaneous price impact for best-bid/ask order-book imbalance in US stocks, not 6h BTC predictive skill from aggregated taker flow. The proposed block is only a testable representation hypothesis. No inference receipt timestamp is established by an archived bar's open/close time.

## Objective and reporting contract

`relative_constraint` computes log1p of modeled excess returns and its running-peak drawdown. This is neither exact log wealth difference `log(1+r_strategy)−log(1+r_BH)` nor `MaxDD(strategy)−MaxDD(BH)`. `relative_cvar_coef` currently weights `ReLU(−net_return−tail_margin)`, a downside hinge; it does not estimate a quantile/CVaR. The alternative `ac.reward_objective: benchmark_absolute_constraint` exists and requests `world_model.reward_mode: absolute`, but requires the reward-support correction above and still compares finite imagined paths with model error. A benchmark rollout is a separate stochastic model trajectory, so pathwise cancellation is not guaranteed merely by matching initial states. The auxiliary `upside_miss_coef`/`downside_hedge_coef` currently use normalized WM reward, which in excess mode is relative return, not the market's up/down state.

Report all fixed arms, BC, and B&H with the same complete validation windows, equal-quarter AlphaEx and MaxDDDelta, base/doubled costs, fixed regime assignment and regime counts, joint-sign quarter counts, turnover/fills/exposure, and exact available-feature masks. A BC-only checkpoint or a zero-update/identical-order actor cannot establish incremental imagination learning. Require recorded AC updates/changed parameters and inspect actual action differences, but do not impose a post-hoc minimum number of trades to remove failures. Distinguish predictive auxiliary-head quality, actual policy economics, and faithful WM→BC→AC deployment. Overall AlphaEx>0/MaxDDDelta<0 is the minimum economic criterion; all-regime mean signs, untouched-forward evidence and robustness/selection controls remain separate. This small reused-validation family cannot establish high-probability, trend-independent precision or a strongest universal model. Hindsight Oracle outcomes are never learned-RL performance.

## Primary sources read

1. Janner et al., *When to Trust Your Model: Model-Based Policy Optimization*, NeurIPS 2019. Short real-state-branched model rollouts and the model-bias/policy-shift tradeoff; experiments are continuous-control tasks, not financial guarantees. https://proceedings.neurips.cc/paper/2019/file/5faf461eff3099671ad63c6f3f094f7f-Paper.pdf
2. Fujimoto & Gu, *A Minimalist Approach to Offline Reinforcement Learning*, NeurIPS 2021, Eq.3–5 and appendix heuristic. BC regularization plus state normalization; original lambda scales Q relative to BC. UniDream instead scales a REINFORCE-style advantage by `td3bc_alpha / max(EMA|adv|,.1)` and separately mixes BC; this is inspired by TD3+BC, not an exact reproduction. Raising its `td3bc_alpha` strengthens the policy-gradient term, not the BC penalty. https://arxiv.org/pdf/2106.06860
3. Yu et al., *MOPO*, NeurIPS 2020, Assumption4.3 and §4.3. Penalized-MDP rationale depends on model-error assumptions; the practical ensemble standard-deviation proxy is explicitly heuristic. https://papers.nips.cc/paper_files/paper/2020/file/a322852ce0df73e204b7e67cbbef0d0a-Paper.pdf
4. Chow et al., *Risk-Sensitive and Robust Decision-Making: a CVaR Optimization Approach*, NeurIPS 2015. An actual CVaR MDP objective has a specified risk level and optimization semantics; it does not justify calling a fixed downside hinge CVaR or proving BTC drawdown constraints. https://proceedings.neurips.cc/paper/2015/hash/64223ccf70bbb65a3a4aceac37e21016-Abstract.html
5. Cont, Kukanov & Stoikov, *The Price Impact of Order Book Events*. Order-book flow imbalance explanatory relation; the bar-taker-flow predictive extrapolation is ours and remains unproven. https://arxiv.org/abs/1011.6402
